## 1. 먼저 내릴 수 있는 결론

**현재 구현에 정보·표현 병목은 실제로 있다. 그러나 이것이 QMIX 대비 성능 부진의
주원인이라는 인과적 증거는 아직 없다.** 프롬프트 교체만으로 해결된다고 보기도 어렵다.
입력 요약 → 계획 → 실행 가능한 보상 사이에서 어떤 정보가 사라지는지 먼저 확인하고,
조건을 맞춘 고정 주기 팔에서 채널의 효용을 확인한 뒤 RSVP를 비교해야 한다.

이번에 실행한 것은 실제 SMAC 8에피소드, 구조적 회귀 확인, 과거 완주 8런 감사,
그리고 동일 상태에 대한 cache-off/temp 0.2 LLM 반복 호출이다. 새 장기 학습은 시작하지 않았다.

## 3. 논문 대조: 확인된 차이와 미확인 사항

- 공식 보충자료는 `epsilon_anneal_time=300000`을 명시한다. 현재 QMIX/LEHCA/RSVP는
  50,000이다. 보충자료는 공개 URL에서 실제 다운로드·텍스트 추출을 확인했다.
  [공식 보충자료](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41598-026-54971-6/MediaObjects/41598_2026_54971_MOESM1_ESM.pdf)
- 현재 스케줄 클래스에서 100k 시점 ε는 **0.05 대 0.6833**이다. 첫 300k에 대한
  ε(t) 적분은 **38,750 대 157,500 (4.06배)**이다. 이는 스케줄 면적 비교이지
  실제 랜덤 행동 수를 관측한 값은 아니다. 성능 영향의 방향은 미측정이다.
- 본문은 Commander가 환경의 관측 가능 정보 요약을 받고 훈련 로그는 받지 않는다고
  설명한다. 현재 학습 러너는 최근 승률·t_env를 요약에 추가한다. 이번 고정 상태 프로브는
  이 훈련 통계를 넣지 않아 입력 상태를 고정했다. 실제 학습 프롬프트 분포와는 차이가 있다.
  [논문 본문](https://www.nature.com/articles/s41598-026-54971-6)
- 본문은 목표의 접지와 보상/마스킹을 설명하지만, 열람한 본문·보충자료만으로 정확한
  원본 프롬프트·접지 구현·모든 F/λ/β 설정을 복원할 수 없다. 따라서 현재 고정 predicate
  방식이 원 코드와 정확히 얼마나 다른지, 자유 코드 생성이 필요했는지는 **UNKNOWN**이다.
- ε300k로 바꾼 LEHCA를 기존 ε50k QMIX와만 비교하면 안 된다. QMIX도 함께 바꾸되,
  기존 강한 QMIX 결과를 지우거나 약한 기준선만 골라 개선으로 보고하지 않는다.

### 4.2 의미 손실의 직접 재현

1. **진형 정보:** 인원·체력·중심점이 같고 적의 분산 배치만 다른 두 합성 snapshot의
   `summary`와 cache key가 모두 같다. cache off도 입력 요약에서 이미 사라진 정보를 복구하지 못한다.
2. **캐시 정보:** 적이 동쪽인 상태와 서쪽인 상태는 요약이 다르지만 cache key가 같다.
   cache off는 이 재사용 문제는 피할 수 있다. 이것이 학습 중 성능에 끼친 양은 미측정이다.
3. **조건 표현:** subgoal의 `condition`, `target_id`, `time_window`는 sanitize 후 모두
   사라진다. 현재 스키마에 해당 필드가 없기 때문이다. 전략의 조건은 실행 보상에 보존되지 않는다.
4. **문장과 보상:** subgoal이 같으면 strategy를 집중사격에서 산개·카이팅으로 바꿔도
   셰이핑은 같다. 특히 masking-off에서는 action_rules도 정책에 전달되지 않는다.
5. **행동 proxy:** 합성 pre=post에서 다섯 유닛이 같은 적을 공격하는 행동을 주면 피해가
   0이어도 focus_fire=0.3이다. 이 보상은 명중/전술 이득이 아니라 공격 대상 집중의 proxy다.
   실제 무효 행동의 반복 보상이 학습 중 발생했다고 주장하는 재현은 아니다.

## 5. 고정 상태 LLM 프로브

설계: ep0의 t=0/4/9/13/18 및 ep7의 t=18, 총 6개 상태 × 기존
default/paper/twostage × 2회. cache off, temperature 0.2,
gpt-oss-20b, reasoning low. 요청은 직렬 실행, 재시도 포함 HTTP 최대 64회 제한.
기존 twostage 구현은 계획 3072, 접지 1024 토큰 상한을 그대로 썼다.

측정값은 동일한 157개 전이에 각 가이던스를 재생한 셰이핑 함수의 차이다.
λ·마스킹·정책 변화·학습은 포함하지 않는다. 같은 상태 두 출력 간 RMS를 반복 변동으로,
서로 다른 상태의 출력 평균 간 RMS를 상태 간 차이로 기록한다. 6상태/2반복으로
통계적 유의성이나 학습 안정성의 일반적 결론을 내리지 않는다.

실제 응답에서 확인한 예:

- ep0/t0 twostage 첫 계획은 정찰, 진형, 특정 적 접근, **팀 총체력 50% 조건 후퇴**를
  제안했다. 접지 후에는 enemy_damage 두 항목, focus_fire, ally_survive,
  retreat_low_health로 바뀌었다. 후퇴는 실제 구현상 **개별 HP 30% 미만·적 중심에서
  멀어지는 이동**이다. 원래 팀 조건·50% 임계값·안전한 위치 조건은 보존되지 않는다.
- 같은 상태의 두 번째 자유 계획은 맵을 5×5로 해석하는 등 입력으로 뒷받침되지 않은
  공간 정보를 덧붙였다. 이는 개별 오류 사례이며 모델 전체 오류율은 아니다.
- 같은 상태의 paper 응답 두 개는 subgoals=[]이고 action_rules만 있었다.
  정상 JSON/valid guidance여도 shaping-only 팔에는 실행 보상이 없는 경우다.

## 6. 후속 실험 우선순위와 판정 규칙

### P1 — 비교 가능성을 먼저 복구

현재 236/237은 완주 후 기술 통계로만 보고한다. 236의 직접 대조군은
**동일 RSVP runner의 fixed F200 / lam40 / masking off / replay shaping /
cache off / temp 0.2 / ε50k**다. 이 팔은 LEHCA shaping-only 대조군이지 완전 LEHCA가 아니다.
같은 1.2M 예산·평가 간격·seed0–3을 사용한다. 다음은 실행 가능한 override 예시이며
이번 감사에서 실행한 명령은 아니다. 서버/슬롯 유효성은 실행 직전 재확인해야 한다.

```bash
# cwd: scripts/, aamas 활성화 및 할당된 학습 자원 안에서 실행
SEEDS="0 1 2 3" EXTRA="t_max=1200000 f_update=200 llm_cache=False llm_temperature=0.2 epsilon_anneal_time=50000 use_action_masking=False use_masking_at_test=False shaping_in_learner=True lambda_floor_frac=0.4" bash run_rsvp_sc2.sh 5m_vs_6m fixed true lehca-shape_F200_lam40_nc_t02 http://n038:8357/v1
```

새 RSVP에는 Q-004 패치가 적용되어 있다. 기존 lam40 RSVP과 합산하지 않는다.
cache+temp를 함께 바꾼 현재 세트는 **결합 설정의 효과**만 측정한다. 캐시 단독 원인을
분리해야 할 때에만 cache off/temp0 팔을 추가한다.

### P2 — 원문 설정 차이는 QMIX와 함께 검증

ε50k/300k × QMIX/고정 F200의 2×2 설계로 탐색 스케줄과 셰이핑의 상호작용을 본다.
P1의 ε50k 팔 및 기존 동일 조건 QMIX를 재사용할 수 있다. ε300k 두 팔만 새 그룹으로
추가하고 다른 조건은 동결한다. 이것은 **원문 ε 설정을 적용한 비교**이지, 모든 접지·
마스킹 차이가 해결된 원 논문 완전 재현이 아니다. 성능을 보고 ε를 고른다면 그 선택은
탐색용 seed와 확인용 seed를 분리해 검증한다.

### P3 — 비싼 접지 재설계 전에 LLM 조건부 가치 확인

고정 F200 LLM 팔이 QMIX보다 나아지는 경우, 같은 보상 스키마/λ로 **사전 고정된
비-LLM 보상 계수** 대조군을 둔다. 계수는 독립 진단 자료에서 확정하고 test return에
맞춰 선택하지 않는다. 이것이 LLM 팔과 동급이면 이득은 동적 의미 추론 없이도 생길 수 있다.
정적 대조군은 새 commander 모드가 필요하므로 현재 baseline에는 구현하지 않았다.

고정 F200에서도 채널 이득이 없으면 RSVP 파라미터 탐색을 우선하지 않는다. 다음 최소
개선 후보는 (a) 관측 가능한 개체별 체력/위치·사거리·cooldown 등 입력의 충실도,
(b) 목표 조건을 명시적으로 표현하고 실행 의미와 일치시키는 접지 스키마다.
먼저 조건별 합성 상태에서 의도한 보상이 구분되는지 테스트하고, 입력 개선과 접지 확장을
서로 다른 ablation으로 비교한다. 유리한 테스트 성능에 맞춰 predicate를 추가하지 않는다.
자유 생성 코드를 바로 실행하는 방식으로 바꾸지는 않는다.

### 모든 학습 팔의 공통 판정

- 공통 예산에서 시간 가중 정규화 AUC, 마지막 10% 평가 평균, seed별 paired 차이,
  seed 변동 및 불확실성을 보고한다. 기존 단순 평가 평균 AUC와 정의를 구분한다.
- 1 seed·초기 100k 승률로 성공/실패를 확정하지 않는다. seed0–3은 최소 비교 세트이며
  n=4 자체가 유의성을 보증하지 않는다. CI가 넓으면 미결로 보고한다.
- 보조 지표: 외부 return·승률·episode length, raw F 및 λF 크기/clip 비율,
  empty subgoals·접지 불일치·실행 보상 변화율, 실제 HTTP·토큰·LLM 대기시간.
- mask-on 팔은 금지/soft-bias 행동 비율과 test masking 유무를 별도 기록한다.
- 성능 향상은 외부 평가에서 판정한다. 가이던스 문장 다양성이나 rule-based 전환
  정렬만으로 효용/검출 정확성을 대신하지 않는다.

## 7. 재현 및 변경 범위

```bash
python analysis/audit_lehca_grounding.py --mode collect --out <새_결과_폴더>
python analysis/audit_lehca_grounding.py --mode analyze --out <새_결과_폴더>
python analysis/audit_lehca_grounding.py --mode llm --out <새_결과_폴더> --api <현재_서버>/v1
python analysis/audit_lehca_grounding.py --mode summarize --out <새_결과_폴더>
```

collect는 SC2 및 aamas 환경이 필요하다. analyze는 저장 궤적 외에 이 저장소의 기존
Sacred/guidance 파일을 읽는다. 출력 파일은 exclusive-create라 같은 파일을 덮어쓰지 않는다.
각 JSON에는 관련 소스 SHA256과 실행 시각이 있다. 입력 trajectory 및 HTTP 원문은
results 아래 로컬 산출물이며 공개 커밋 대상으로 추가하지 않았다.

추가 파일은 진단 스크립트·이 부록이며, 실험 로그/README/셰어보드에는 연결 및 결론만
추가한다. 되돌릴 때 이 파일들과 이번에 추가한 문서 절만 제거하면 된다. 기존 결과,
학습 소스, baseline config는 보존했다.
