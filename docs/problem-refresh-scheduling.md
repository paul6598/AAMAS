# 문제 정의 초안: Commander refresh 스케줄링 (2026-08-29)

목적: "F_update를 동적으로" 이전에 **우리가 푸는 문제가 정확히 무엇인지** 고정한다.
해결 방안은 다루지 않는다. 관련연구: docs/related-work-llm-call-scheduling.md.
기준 코드: algorithm/lehca/runner.py `_maybe_refresh_commander`.

## 1. 대상 시스템에서 F_update가 실제로 하는 일

매 env 스텝 t에서 runner는 `t_global − t_last_refresh ≥ F_update`이면 **refresh**를 한다:
① 스냅샷 → 요약 d_t 재구축, ② cache_key(d_t)로 Commander 호출(키 적중 시 LLM 호출 없음),
③ 반환 가이던스 g = (subgoals, action_rules)로 `state.guidance` 교체.
그 외 스텝은 **직전 g를 그대로 사용**한다. g는 두 채널로 학습에 개입한다:

| 채널 | 매 스텝 일어나는 일 | 낡은 g의 효과 |
|---|---|---|
| 셰이핑 | subgoal predicate를 (s_t, a_t, s_{t+1})에 평가해 F_t 저장, 학습 시 λ_now·F_t 합성 | predicate가 현 상태에 자체 그라운딩되므로 대체로 "무뎌짐"(대상 소멸 시 0). 단 규칙 집합이 바뀌면 버퍼 안의 F_t 정의가 이질화 |
| 마스킹 | action_rules의 심볼 토큰을 현 스냅샷에 재그라운딩해 hard/soft 마스크 생성 (Eq. 7) | 그라운딩은 최신이지만 **규칙 선택**은 낡음. 교전 중 나온 forbid가 다음 에피소드 접근 단계에 적용됨 |

즉 F_update는 "가이던스 강도"가 아니라 **규칙 선택의 신선도**와 **LLM 호출 수**를
동시에 정한다. F→∞는 가이던스 off가 아니라 첫 규칙의 영구 고정이다.

## 2. 왜 고정 F_update가 문제인가 — 근거

**(a) 가이던스가 에피소드 경계를 넘는다 — 구조적 사실, 효과는 미측정.**
에피소드 길이 50–100 < F=200이므로 교전 중 만들어진 g가 다음 에피소드의 접근
단계에 적용된다. 프로빙(docs/probe-commander-20260829.md)에서 교전·저체력 상태의
LLM은 `move_all` forbid를 내므로, 이 규칙이 접근 단계에 남으면 이동 자체가
봉쇄된다 — 낡은 규칙이 해로울 수 있는 구체적 경로. 그러나 **이것이 실제로 얼마나
자주, 얼마나 크게 행동·보상을 바꾸는지는 아직 재지 않았다.** (cache_key 변화율
같은 상태-공간 지표는 200스텝이면 자명하게 1에 가깝고, 키는 응답 재사용용이지
"새 가이던스가 필요한가"의 탐지기가 아니므로 근거가 되지 못한다. rule Commander는
키가 99.6% 바뀌어도 가이던스는 34%만 바뀜.) 낡음은 §4의 **효과 공간** 지표로 잰다.

**(b) 가이던스는 상태 의존적이고, 그 정도는 Commander에 따라 다르다.** 같은 상태열에서
연속 refresh 간 g 변화율: **LLM 98.4% vs rule 33.8%** (같은 키 → 캐시 → 동일 g이므로
변화는 전부 키 변화에서 옴; 비결정성 아님). LLM은 미세한 상태 차이에 규칙을 바꾼다
→ refresh가 잦을수록 규칙 churn이 커진다.

**(c) 잦은 refresh는 공짜가 아니다 — 비용과 비정상성.** LLM 호출 ~5초, 벽시계 오버헤드
2s3z +40–70%, 5m6m +13%. F100 런은 F800 런의 ~1/3 속도(70k vs 240k, 동일 시간).
문헌: 매 에피소드 재질의 시 QMIX 붕괴(2607.04470), 매 스텝 재계획 시 불안정
(2509.03581), chattering(2606.25509).

**(d) 가이던스의 가치는 맵·학습 단계에 따라 부호가 바뀐다** (final-report 발견 #3:
5m6m 유익 / 2s3z 초반만 / 3s5z 유해). 따라서 최적 refresh 시점·빈도가 맵마다 다를
가능성이 높고, 하나의 F로는 못 맞춘다.

**(e) 논문은 F_update 값·ablation을 제공하지 않으며** 적응 호출을 future work로 명시.
SMAC/QMIX에서 Commander 주기 스윕은 문헌에 없다.

## 3. 문제의 형식화

- 학습 루프: LEHCA (Commander C, 키 캐시, QMIX 학습기 L, λ 스케줄 고정).
- **refresh 정책** π: 스텝 t의 관측 가능한 이력 h_t (스냅샷/키, 현 g, 학습 통계) →
  a_t ∈ {keep, refresh}. 고정 주기 π_F는 a_t = 1[t − t_last ≥ F].
- 비용: c_t = 1[a_t = refresh ∧ 캐시 미스] (LLM 호출). 총 호출 N(π). 보조 지표로 벽시계.
- 성능: J(π) = AUC_early (Eq. 9, 예산 첫 20%), final(last-10%).
- **문제**: (J, N) 평면에서 π_F 계열(F ∈ {100,…,800,∞})을 지배하는 π가 존재하는가?
  존재한다면 h_t의 어떤 성분이 그것을 가능하게 하는가?

이는 test-time 플랜 요청(When2Ask)이 아니라 **학습 데이터 생성 과정에 개입하는
training-time 스케줄링**이다: refresh 결정이 버퍼에 들어가는 F_t·행동 분포를 바꾼다.

## 4. 측정 가능한 중간량 (문제를 "설명"하는 변수)

| 이름 | 정의 | 어디서 | 용도 |
|---|---|---|---|
| **효과 낡음 (마스크)** | 스텝 t에서 build_masks(g_active, s_t) vs build_masks(g\*(s_t), s_t): hard 마스크가 다른 에이전트 비율, 틸트 argmax가 다른 비율 | shadow 모드(아래) | 낡은 규칙이 실제 행동을 바꾸는 시간 비율 |
| **효과 낡음 (셰이핑)** | \|F_t(g_active) − F_t(g\*(s_t))\| 평균 | shadow 모드 | 낡은 서브골이 보상을 바꾸는 크기 |
| **규칙 churn** | 10k 스텝당 서로 다른 g 버전 수 / g 평균 수명 | 덤프 | 비정상성 크기. Commander·F 의존 |
| **가이던스 영향** | `mask_override_rate`, `mask_forbid_frac`, mean λ·F_t | wandb | g가 실제로 행동·보상을 바꾸는가 (0이면 refresh 무의미) |
| **무효화 이벤트율** | 현 g가 참조한 적 타입 전멸, subgoal predicate 연속 0 | 덤프+스냅샷 | 낡음 중 "확실히 틀린" 부분 |
| **호출 수 / 캐시 적중률** | N, hits/(hits+calls) | wandb | 비용 |
| **버퍼 이질성** | 샘플 배치에 섞인 g 버전 수 | learner | (c)의 기전 확인용 |

**Shadow 모드** (효과 낡음 측정용, 1런): 학습은 F=200 그대로 두고, 매 k스텝
(k=1 또는 10) Commander를 추가로 호출해 g\*(s_t)를 얻되 **적용하지 않고** 로그만
남긴다. 그 자리에서 g_active와 g\*로 마스크·F_t를 둘 다 계산해 차이를 기록. 한
런의 (s_t, g\*(s_t)) 시퀀스가 있으면 임의의 F·per-episode·키 변화 트리거를
오프라인 재생해 F별 효과-낡음 곡선을 그릴 수 있다. LLM 비용은 들지만 한 번이면
된다. 상태 공간 지표(키 변화율)는 자명하므로 쓰지 않는다.

## 5. 문제를 확립하는 가설과 판별 실험 (해법 아님)

| # | 가설 | 판별 | 예측 |
|---|---|---|---|
| H1 | J는 F에 비단조(중간 최적) | F 스윕 {100,200,400,800} (진행 중) + F=∞(첫 g 고정) + per-episode | 둔감하면 문제는 비용 최소화로 축소 |
| H0 | 낡은 g는 실제로 행동·보상을 바꾼다 (효과 낡음 > 0, F에 따라 증가) | shadow 모드 1런 → F별 효과-낡음 곡선 | 0에 가까우면 A축 문제 자체가 약함 |
| H2 | 큰 F의 손실은 **낡음** 때문 | 같은 N으로 (i) π_F=800 vs (ii) 효과 낡음이 큰 시점에 refresh | (ii) > (i)면 낡음이 원인 |
| H3 | 작은 F의 손실은 **churn**(비정상성) 때문 | F=100에서 캐시 on vs off(LLM 비결정성 추가), 버퍼 이질성 로깅 | off가 더 나쁘면 churn 원인 |
| H4 | **채널 비대칭**: 마스킹이 셰이핑보다 F에 민감 | F 스윕을 v4(shaping-only)와 M5 설정(마스킹 on)에서 각각 | 마스킹 on의 기울기가 큼 |
| H5 | 에피소드 경계 refresh가 싼 이득 | per-episode refresh vs F=200 (N 비슷) | per-episode ≥ F=200 |
| H6 | 같은 예산 B라도 **배치**가 결과를 바꿈 (Torrey–Taylor) | N을 고정하고 early-concentrated vs uniform | 차이 있으면 A축 명제 성립 |
| H7 | 민감도는 가이던스 headroom이 있는 맵에서 크다 | 5m6m에서 F 스윕 재현 | 2s3z보다 5m6m에서 F 효과 큼 |

H7이 중요하다: 2s3z는 QMIX가 포화되는 맵이라 F 스윕이 평평하게 나와도 "문제 없음"이
아니라 "이 맵엔 headroom이 없음"일 수 있다. 문제 확립의 본 무대는 5m6m.

## 6. 범위 결정 (사용자 확인 필요)

1. **채널**: 마스킹 on(논문 충실, M5 어휘) + shaping을 기본 설정으로 하되, H4를 위해
   shaping-only도 스윕. — M5 판정에 조건부.
2. **비용 단위**: 1차 = LLM 호출 수(캐시 미스), 2차 = 벽시계. refresh 횟수 자체는 비용
   아님(키 적중 시 공짜).
3. **시간 범위**: training-time만. test 에피소드는 논문 프로토콜(최신 g, refresh 없음) 유지.
4. **λ·β 스케줄 고정**(B축은 범위 밖). 단 λ 감쇠가 v4에서 ~200k에 0이 되므로 shaping
   채널의 F 효과는 첫 200k에 국한됨을 명시.
5. **맵**: 2s3z(진행 중) → 5m6m(본 무대) → 3s5z(유해 레짐, 참고).
6. **판정 지표**: AUC_early + final(last-10%) + N. 시드 ≥3.

## 7. 리스크

- F 스윕이 2s3z에서 평평 → H7로 5m6m 확인 전엔 결론 금지.
- LLM-MARL(2506.04251)이 SC2에서 호출 게이트를 이미 보고 → 우리 차별점은 "규칙 수준
  가이던스의 staleness·churn·off-policy 버퍼"라는 **기전 분석**과 주기 스윕. 기전 없이
  게이트만 제안하면 증분 연구로 읽힘.
- 효과 낡음이 작게 나오면(H0 기각) "F_update 스케줄링"은 비용 문제로만 남는다 —
  이 경우 연구 프레임을 재검토.
