# 문제 정의 초안: Commander refresh 스케줄링 (2026-08-29)

목적: "F_update를 동적으로" 이전에 **우리가 푸는 문제가 정확히 무엇인지** 고정한다.
해결 방안은 다루지 않는다. 관련연구: docs/related-work-llm-call-scheduling.md.
기준 코드: algorithm/lehca/runner.py `_maybe_refresh_commander`.

## 1. 대상 시스템에서 F_update가 실제로 하는 일

매 env 스텝 t에서 runner는 `t_global − t_last_refresh ≥ F_update`이면 **refresh**를 한다:
① 스냅샷 → 요약 d_t 재구축, ② cache_key(d_t)로 Commander 호출(키 적중 시 LLM 호출 없음),
③ 반환 가이던스 g = (subgoals, action_rules)로 `state.guidance` 교체.
그 외 스텝은 **직전 g를 그대로 사용**한다. g는 두 채널로 학습에 개입한다:

| 채널 | 매 스텝 일어나는 일 | 낡은 g의 효과 |
|---|---|---|
| 셰이핑 | subgoal predicate를 (s_t, a_t, s_{t+1})에 평가해 F_t 저장, 학습 시 λ_now·F_t 합성 | predicate가 현 상태에 자체 그라운딩되므로 대체로 "무뎌짐"(대상 소멸 시 0). 단 규칙 집합이 바뀌면 버퍼 안의 F_t 정의가 이질화 |
| 마스킹 | action_rules의 심볼 토큰을 현 스냅샷에 재그라운딩해 hard/soft 마스크 생성 (Eq. 7) | 그라운딩은 최신이지만 **규칙 선택**은 낡음. 교전 중 나온 forbid가 다음 에피소드 접근 단계에 적용됨 |

즉 F_update는 "가이던스 강도"가 아니라 **규칙 선택의 신선도**와 **LLM 호출 수**를
동시에 정한다. F→∞는 가이던스 off가 아니라 첫 규칙의 영구 고정이다.

## 2. 왜 고정 F_update가 문제인가 — 근거

**(a) 가이던스가 에피소드 경계를 넘는다 — 구조적 사실, 효과는 미측정.**
에피소드 길이 50–100 < F=200이므로 교전 중 만들어진 g가 다음 에피소드의 접근
단계에 적용된다. 프로빙(docs/probe-commander-20260829.md)에서 교전·저체력 상태의
LLM은 `move_all` forbid를 내므로, 이 규칙이 접근 단계에 남으면 이동 자체가
봉쇄된다 — 낡은 규칙이 해로울 수 있는 구체적 경로. 그러나 **이것이 실제로 얼마나
자주, 얼마나 크게 행동·보상을 바꾸는지는 아직 재지 않았다.** (cache_key 변화율
같은 상태-공간 지표는 200스텝이면 자명하게 1에 가깝고, 키는 응답 재사용용이지
"새 가이던스가 필요한가"의 탐지기가 아니므로 근거가 되지 못한다. rule Commander는
키가 99.6% 바뀌어도 가이던스는 34%만 바뀜.) 낡음은 §4의 **효과 공간** 지표로 잰다.

**(b) 가이던스는 상태 의존적이고, 그 정도는 Commander에 따라 다르다.** 같은 상태열에서
연속 refresh 간 g 변화율: **LLM 98.4% vs rule 33.8%** (같은 키 → 캐시 → 동일 g이므로
변화는 전부 키 변화에서 옴; 비결정성 아님). LLM은 미세한 상태 차이에 규칙을 바꾼다
→ refresh가 잦을수록 규칙 churn이 커진다.

**(c) 잦은 refresh는 공짜가 아니다 — 비용과 비정상성.** LLM 호출 ~5초, 벽시계 오버헤드
2s3z +40–70%, 5m6m +13%. F100 런은 F800 런의 ~1/3 속도(70k vs 240k, 동일 시간).
문헌: 매 에피소드 재질의 시 QMIX 붕괴(2607.04470), 매 스텝 재계획 시 불안정
(2509.03581), chattering(2606.25509).

**(d) 가이던스의 가치는 맵·학습 단계에 따라 부호가 바뀐다** (final-report 발견 #3:
5m6m 유익 / 2s3z 초반만 / 3s5z 유해). 따라서 최적 refresh 시점·빈도가 맵마다 다를
가능성이 높고, 하나의 F로는 못 맞춘다.

**(e) 논문은 F_update 값·ablation을 제공하지 않으며** 적응 호출을 future work로 명시.
SMAC/QMIX에서 Commander 주기 스윕은 문헌에 없다.

## 3. 문제의 형식화

- 학습 루프: LEHCA (Commander C, 키 캐시, QMIX 학습기 L, λ 스케줄 고정).
- **refresh 정책** π: 스텝 t의 관측 가능한 이력 h_t (스냅샷/키, 현 g, 학습 통계) →
  a_t ∈ {keep, refresh}. 고정 주기 π_F는 a_t = 1[t − t_last ≥ F].
- 비용: c_t = 1[a_t = refresh ∧ 캐시 미스] (LLM 호출). 총 호출 N(π). 보조 지표로 벽시계.
- 성능: J(π) = AUC_early (Eq. 9, 예산 첫 20%), final(last-10%).
- **문제**: (J, N) 평면에서 π_F 계열(F ∈ {100,…,800,∞})을 지배하는 π가 존재하는가?
  존재한다면 h_t의 어떤 성분이 그것을 가능하게 하는가?

이는 test-time 플랜 요청(When2Ask)이 아니라 **학습 데이터 생성 과정에 개입하는
training-time 스케줄링**이다: refresh 결정이 버퍼에 들어가는 F_t·행동 분포를 바꾼다.

### 3b. 등가 정식화: "얼마나 유지할지" (가이던스 = 옵션)

스텝 단위 keep/refresh 대신, refresh 시점 r에 **유지 길이 τ_r**(또는 종료 조건)을
정하는 문제로 볼 수 있다 — 가이던스를 옵션으로, F_update를 옵션 길이로 보는
SMDP 관점(action repetition: FiGAR/TempoRL/TACOS, option termination, deliberation
cost). 모든 베이스라인이 τ의 선택으로 통일된다:

| 정책 | τ |
|---|---|
| 고정 F | τ ≡ F |
| per-episode | 에피소드 끝까지 |
| once (F→∞) | ∞ |
| 이벤트 트리거 | 종료 조건 β(s)가 참이 될 때까지 |
| repetition 계열 | 상태·가이던스 조건부로 τ 선택 (open-loop) |

두 구조: (i) **open-loop 길이** — refresh 때 τ를 정하고 그동안 보지 않음(싸지만
비반응적); (ii) **종료 조건** — refresh 때 "유효 조건"을 정하고 매 스텝 심볼릭
검사(공짜). (ii)는 LLM이 자기 가이던스의 유효 조건을 predicate로 선언하는 형태
(DoReMi식)로 우리 semantic interface에 바로 얹힌다. Deliberation cost η는
"η 이상 나아질 때만 종료"로 chattering과 호출 비용을 한 항에 묶는다.

제약: action repetition에서는 τ 정책의 보상이 환경 리턴이지만, 우리는
training-time이라 τ의 가치가 **학습 진전으로 지연**돼 나타난다(LeCTR의 credit
assignment 문제). 따라서 τ를 학습으로 얻는 것은 어렵고, 문제 정의 단계에서
"τ는 학습 신호가 약하다"를 전제로 둔다.

### 3c. 멀티에이전트에서 달라지는 것 (related-work §4b)

τ 문헌(FiGAR/TempoRL 등)은 단일 에이전트다. 우리 설정이 추가하는 것:

1. **가이던스는 팀 공유, 유효성은 에이전트·규칙별.** Commander 호출은 1회지만
   출력은 수명이 다른 규칙·서브골의 집합이고(`kill_type:X`는 X 전멸까지,
   `retreat_low_health`는 항상, `forbid move_all`은 교전 중만), 같은 규칙이
   에이전트마다 다른 시점에 낡는다. → τ의 단위가 **가이던스(동기) vs 규칙·에이전트
   타입(비동기)** 라는 선택지가 생긴다. 규칙 단위 종료는 LLM 재호출 없이 재컴파일로
   되므로(compiler가 이미 매 스텝 그라운딩) 비용 0인 **부분 refresh**가 존재한다.
   형식 틀: MacDec-POMDP·ToMacVF(비동기 매크로 액션 + 값 분해); Tang et al.은 동기
   vs 비동기 종료를 설계 축으로 명시.
2. **F_update는 QMIX 계열 계층 MARL의 상위 결정 주기와 같은 하이퍼파라미터다**
   (RODE c=5, HAVEN k=3, HSD 10, ALMA 3–5, COPA T=4). 보고된 ablation은 전부 내부
   최적 — 특히 COPA는 T 스윕(2–24)에서 T=4가 최적이고 "작을수록 좋다"를 명시적으로
   반박하며, 그 이유를 "코치는 에이전트를 시간적으로 일관되게 만들 때 유용"으로
   설명한다. 이는 우리 (c)의 churn 가설과 같은 기전이다.
3. **MARL 고유 트레이드오프**(Han et al. 2019): 긴 유지는 팀원 상황 변화에 늦게
   반응하고, 잦은 전환은 다른 에이전트가 의존하는 신호를 불안정하게 만든다.
   팀 공유 가이던스에서 이 긴장은 단일 에이전트보다 크다.
4. **최근접 선례 COPA의 한계**가 곧 우리 문제의 정의다: COPA는 고정 T 격자 위에서
   "바뀐 게 적으면 안 보낸다"(β 임계)만 하므로 주기를 늘릴 수만 있고 줄이지 못하며,
   β는 수동이다. 우리는 (i) 격자 밖에서 앞당기는 트리거, (ii) 규칙·타입 단위 부분
   refresh, (iii) LLM이라 재호출 비용이 크고 캐시가 있다는 비용 구조 — 세 점에서
   다르다.

### 3d. 이론적 계산법: 복종 regret (PDL) + 동적 PBRS

**역할 정정 (2026-08-29 논의)**: 아래 복종 regret c_t는 "학습기의 Q 기준으로
가이던스를 얼마나 신뢰할 것인가"를 재는 **신뢰 게이트**이지, "상황이 바뀌어
가이던스가 낡았는가"를 재는 양이 아니다. c_t ≥ 0 항상이고 "가이던스가 더 낫다"는
정보를 담지 않으므로, 가이던스가 학습기보다 낫다는 전제 하의 A축(상황 변화 →
예전 가이던스 역효과) 트리거로는 부적합. A축 트리거는 Commander 입출력 공간에서
정의해야 한다: (1) 규칙별 유효 조건(precondition) 위반 → 규칙 단위 폐기,
(2) 반사실 가이던스 C(d_t)와의 효과 거리(캐시 적중 시 정확, 아니면 Commander
모방 모델로 예측). regret은 과신(β 스케일)·유해 맵(3s5z) 대비 안전장치(B축)로
분리해 둔다. 동적 PBRS는 결정 규칙이 아니라 "refresh 시점이 셰이핑을 통해
최적성을 해치지 않는다"는 허가증이다. 어떤 A축 트리거든 S0(shadow 런으로
낡음의 효과 크기 측정)가 선행.

핵심: "낡음"을 상태 공간이 아니라 **가치 공간**에서 정의한다. 두 채널에 표준 정리
하나씩.

**기호.** 가이던스 g = (서브골 → potential Φ_g, 규칙 → W_g, M_g). 에이전트 유틸리티
Q_i, 믹서 Q_tot (QMIX, 단조). 가이던스 하의 행동 정책
π_g^i(s) = argmax_{a: M_g(a)=1} [Q_i(s,a) + β log W_g(s,a)], 무가이던스 greedy u*(s) =
argmax_u Q_tot(s,u) (IGM으로 에이전트별 argmax).

**채널 1 — 셰이핑: 동적 potential-based shaping.**
- Ng–Harada–Russell (ICML 1999): F = γΦ(s′) − Φ(s)는 최적 정책 보존.
- Devlin & Kudenko (AAMAS 2012): Φ가 시간에 따라 변해도 F_t = γΦ(s′,t′) − Φ(s,t)면
  보존. MAS 판(AAMAS 2011): Nash 균형 보존.
- 적용: 서브골을 potential Φ_g(s) = Σ_j w_j φ_j(s)로 정의 (φ_kill_type = −타입 X 잔여
  HP 비율, φ_protect = 아군 타입 HP 비율 등). refresh로 g_t가 바뀌는 것은 정확히
  동적 potential이므로 F_t = γΦ_{g_{t+1}}(s_{t+1}) − Φ_{g_t}(s_t)이면 **어떤 refresh
  정책이든 최적 정책 불변.** λ_t Φ도 potential이므로 λ 감쇠도 포함. 리플레이에는
  (Φ_{g_t}(s_t), Φ_{g_{t+1}}(s_{t+1}))를 저장하면 learner 시점 합성 가능.
- 결과: F·refresh는 수렴 속도·분산·비용에만 영향 → 2607.04470의 비정상성·버퍼 오염
  문제가 정의상 소거. 제약: 행동 기반 predicate(focus_fire)는 potential이 아님 →
  제외하거나 별도 채널로.

**채널 2 — 마스크: 복종 regret.**
- 정의: c_t(g) = Q_tot(s_t, u*(s_t)) − Q_tot(s_t, u_g(s_t)) ≥ 0. "현재 가치 추정
  기준으로 가이던스에 복종해 포기한 advantage." 중앙 학습 시 믹서 forward 1회로
  계산(에이전트별 합 Σ_i[max_a Q_i − Q_i(π_g^i)]은 단조성에 의한 프록시).
- Performance difference lemma (Kakade & Langford 2002):
  J(π*) − J(π_g) = (1/(1−γ)) · E_{s∼d^{π_g}}[c_t(g)]  (Q가 참값일 때 등식).
- **트리거**: 현 가이던스 g_r의 누적 손실 L_r = Σ_{t≥t_r} γ^{t−t_r} c_t(g_r).
  Harb et al. (AAAI 2018) deliberation cost의 최적 종료("전환 이득 > η")를 계산
  가능한 하한으로 대체: 전환 이득 ≥ L_r − L_r(g*) ≥ L_r − (g* 캐시 적중 시 정확값 |
  미스 시 0). → 규칙 "L_r > η면 refresh(또는 폐기)". η = 호출 비용의 리턴 환산.
- **강도**: 틸트가 argmax를 바꾸려면 β·Δlog W > Q-gap. c_t ≤ ε을 보장하려면
  β_t ≤ ε / max Δlog W — 신뢰영역형 β (CPI/TRPO의 정책 변화 상계와 같은 논리).
- **자동 페이드아웃**: Q가 정확해질수록 Q와 충돌하는 규칙의 c_t가 커져 스스로
  폐기 → B축(단계별 개입)이 별도 스케줄 없이 따라옴.

**매 스텝 절차 (LLM 호출 0).**
1. u* ← 에이전트별 argmax Q_i; u_g ← 가이던스 하 선택. c_t ← Q_tot(u*) − Q_tot(u_g).
2. L_r += γ^{t−t_r} c_t. (캐시에 key(s_t)가 있으면 c_t(g*)도 계산해 L_r(g*) 누적.)
3. L_r − L_r(g*) > η → refresh (캐시 미스면 LLM 호출, 적중이면 무료 교체).
4. β_t ← min(β_0, ε / max Δlog W).

**보장하는 것 / 못 하는 것.**
- 보장: 셰이핑은 refresh와 무관하게 최적 정책 보존. 마스크는 "현재 Q 기준" 손실이
  η로 상계.
- 못 함: Q는 학습 중 추정치. 가이던스가 유익한 순간(Q가 틀렸을 때)에도 c_t가
  크다 — 이때의 충돌은 "좋은 충돌". 따라서 트리거는 초반에 보수적으로 작동하며
  초반을 얼마나 신뢰할지는 η(또는 ε 스케줄)에 남는다. 이론으로 완전히 닫히지 않는
  자유도 1개.

**우리 데이터와의 정합.** β=0.5 → 틸트 0.35–0.55 ≫ q_gap 0.06 → c_t 큼 → 해악
(S1/M4/M5); β=0.1 → 틸트 0.07–0.16 ≈ q_gap → 무해(M3/M6). shaping-only에선 마스크
regret이 0이고 λ→0이라 F∞ 손실이 작음(스윕). 즉 이 계산법은 이미 관측된 세 현상을
한 양으로 설명한다.

**검증 순서.** (i) M3/M6 로그(q_gap, override)로 c_t 시간 곡선 오프라인 → η의
자릿수; (ii) potential형 서브골로 shaping 교체 후 F∞ vs F200 재측정(이론상 동일
final); (iii) 온라인 트리거 vs 고정 F, (AUC, 호출 수) Pareto, 5m6m 포함.

## 4. 측정 가능한 중간량 (문제를 "설명"하는 변수)

| 이름 | 정의 | 어디서 | 용도 |
|---|---|---|---|
| **효과 낡음 (마스크)** | 스텝 t에서 build_masks(g_active, s_t) vs build_masks(g\*(s_t), s_t): hard 마스크가 다른 에이전트 비율, 틸트 argmax가 다른 비율 | shadow 모드(아래) | 낡은 규칙이 실제 행동을 바꾸는 시간 비율 |
| **효과 낡음 (셰이핑)** | \|F_t(g_active) − F_t(g\*(s_t))\| 평균 | shadow 모드 | 낡은 서브골이 보상을 바꾸는 크기 |
| **규칙 churn** | 10k 스텝당 서로 다른 g 버전 수 / g 평균 수명 | 덤프 | 비정상성 크기. Commander·F 의존 |
| **가이던스 영향** | `mask_override_rate`, `mask_forbid_frac`, mean λ·F_t | wandb | g가 실제로 행동·보상을 바꾸는가 (0이면 refresh 무의미) |
| **무효화 이벤트율** | 현 g가 참조한 적 타입 전멸, subgoal predicate 연속 0 | 덤프+스냅샷 | 낡음 중 "확실히 틀린" 부분 |
| **호출 수 / 캐시 적중률** | N, hits/(hits+calls) | wandb | 비용 |
| **버퍼 이질성** | 샘플 배치에 섞인 g 버전 수 | learner | (c)의 기전 확인용 |

**Shadow 모드** (효과 낡음 측정용, 1런): 학습은 F=200 그대로 두고, 매 k스텝
(k=1 또는 10) Commander를 추가로 호출해 g\*(s_t)를 얻되 **적용하지 않고** 로그만
남긴다. 그 자리에서 g_active와 g\*로 마스크·F_t를 둘 다 계산해 차이를 기록. 한
런의 (s_t, g\*(s_t)) 시퀀스가 있으면 임의의 F·per-episode·키 변화 트리거를
오프라인 재생해 F별 효과-낡음 곡선을 그릴 수 있다. LLM 비용은 들지만 한 번이면
된다. 상태 공간 지표(키 변화율)는 자명하므로 쓰지 않는다.

## 5. 문제를 확립하는 가설과 판별 실험 (해법 아님)

명명: 이 연구의 가설은 **S**(scheduling)+순번, wandb 그룹은 `SCHED_<내용>`. 기존
캠페인 접두(DIAG_A–F, G, H, M, SWEEP_F, OBS)와 구분하기 위함 — H4/H6 등은 8/27
AUC 캠페인의 런 이름이므로 재사용하지 않는다.

| # | 가설 | 판별 | 예측 |
|---|---|---|---|
| S1 | J는 F에 비단조(중간 최적) | F 스윕 {100,200,400,800} + F=∞(첫 g 고정) + per-episode | 둔감하면 문제는 비용 최소화로 축소 |
| | **결과(2s3z, v4 shaping-only, docs/masking-fupdate-verdict-20260829.md)**: F100 0.367(n=2) / F200 0.388(n=3) / F400 0.313 / F800 0.352 / F∞ 0.326(n=2) → **약한 민감**. 첫 g 영구 고정 손실 −0.06(~1σ). 같은 캠페인에서 마스킹 해악 = β 스케일(β=0.1이면 무해)로 확정 → 개입 강도가 시점보다 훨씬 민감. | | 2s3z만으로 A축 단독 스토리는 약함. S4(β=0.1 마스킹 on에서 F 스윕)·S7(5m6m)이 사활. 아이디어는 강도×유효성×예산 결합 방향(세션 논의 2026-08-29 저녁) |
| S0 | 낡은 g는 실제로 행동·보상을 바꾼다 (효과 낡음 > 0, F에 따라 증가) | shadow 모드 1런 → F별 효과-낡음 곡선 | 0에 가까우면 A축 문제 자체가 약함 |
| S2 | 큰 F의 손실은 **낡음** 때문 | 같은 N으로 (i) π_F=800 vs (ii) 효과 낡음이 큰 시점에 refresh | (ii) > (i)면 낡음이 원인 |
| S3 | 작은 F의 손실은 **churn**(비정상성) 때문 | F=100에서 캐시 on vs off(LLM 비결정성 추가), 버퍼 이질성 로깅 | off가 더 나쁘면 churn 원인 |
| S4 | **채널 비대칭**: 마스킹이 셰이핑보다 F에 민감 | F 스윕을 v4(shaping-only)와 M5 설정(마스킹 on)에서 각각 | 마스킹 on의 기울기가 큼 |
| S5 | 에피소드 경계 refresh가 싼 이득 | per-episode refresh vs F=200 (N 비슷) | per-episode ≥ F=200 |
| S6 | 같은 예산 B라도 **배치**가 결과를 바꿈 (Torrey–Taylor) | N을 고정하고 early-concentrated vs uniform | 차이 있으면 A축 명제 성립 |
| S7 | 민감도는 가이던스 headroom이 있는 맵에서 크다 | 5m6m에서 F 스윕 재현 | 2s3z보다 5m6m에서 F 효과 큼 |

S7이 중요하다: 2s3z는 QMIX가 포화되는 맵이라 F 스윕이 평평하게 나와도 "문제 없음"이
아니라 "이 맵엔 headroom이 없음"일 수 있다. 문제 확립의 본 무대는 5m6m.

## 5a. S0 상세 설계 — 에피소드 내 국면 전환 전제(P1, P2) 검증

기여점을 "에피소드 내 국면 전환에 대한 강건함"으로 잡으면 해법 이전에 두 전제가
성립해야 한다. 둘 다 **학습된 정책을 고정하고 테스트 시점에** 확인한다 — 학습
동학이 섞이지 않고, 비용은 LLM 호출뿐이다(≈5 s/호출, low effort 기준).

- **P1** LLM은 같은 에피소드 안에서 국면이 바뀌면 *효과가 다른* 규칙을 낸다.
- **P2** 전환 전에 받은 규칙을 계속 쓰면 전환 후 성능이 떨어진다(= 더 자주 갱신하면 오른다).

### 전제 확인의 방법론적 제약 (기존 덤프에서 확인된 사실)
- 저장된 체크포인트가 없다(`save_model` 전부 False). 새 학습 1런 필요.
- temperature 0.2에서 연속 LLM 호출의 `action_rules` 완전 일치율은 0–1%
  (M3/OBS/P6 덤프 전부). **문자열 일치로는 국면 변화와 샘플링 노이즈를 구분할 수
  없다** → 비교는 효과 공간(같은 상태에서 컴파일한 마스크·틸트 argmax)에서 하고,
  **같은 상태 반복 호출로 노이즈 바닥선을 먼저 잰다.**
- 2s3z 에피소드 ≈ 55 스텝, F=200 ⇒ 에피소드당 갱신 0–1회. 이 프레임의 비교군은
  F=200이 아니라 **F=ep(에피소드 시작 갱신)과 F_test ∈ {25, 10, 5}** 이다.

### 단계 0 — 체크포인트 확보 (학습 1런)
2s3z, M3 설정(LLM, full 어휘, β=0.1, F=200, dt_observable=True), `save_model=True
save_model_interval=50000`, 500k. wandb 그룹 `SCHED_ckpt_2s3z`. 부산물로 S4의
F=200 β=0.1 점 하나를 겸한다. 평가는 최종 체크포인트와 250k 체크포인트 두 개로
한다(정책 성숙도에 따른 차이 확인).

### E1 — P1: 국면 의존성 (shadow, 개입 없음)
- 정책·가이던스: 체크포인트 그리디 정책, β=0.1 마스킹, **F=ep** 로 실행.
- 매 k=5 스텝마다 shadow 호출(캐시 off, temperature 0.2 그대로)로 g\*_t 를 얻되
  적용하지 않는다. 각 shadow 시점마다 **2회 독립 호출**(노이즈 바닥선용).
- 거리 d(g, g′; s): 같은 상태 s에서 build_masks 후 (i) 살아있는 에이전트×avail
  행동 중 hard가 다른 비율, (ii) 체크포인트 Q로 계산한 틸트 argmax가 다른
  에이전트 비율, (iii) soft 가중치 L1. (ii)가 주 지표(행동으로 드러나는 차이).
- 산출:
  - D_noise = E[d(g\*⁽¹⁾_t, g\*⁽²⁾_t; s_t)] — 같은 상태, 다른 샘플
  - D_stale(Δ) = E[d(g\*_{t−Δ}, g\*_t; s_t)] — Δ 스텝 전 가이던스를 현 상태에 적용
  - 이벤트 마커(스냅샷 차분): 첫 아군/적군 사망, 적 유닛 타입 전멸, 아군 수 <
    적군 수 역전, 체력 버킷 하락, engaged↔approaching 전환. 이벤트 전후 창에서
    D_stale 점프 크기.
  - 규칙 텍스트 로그(무엇이 바뀌는지: 예 Stalker 전멸 후 attack_type 표적 전환).
- **판정**: D_stale(Δ)가 Δ에 따라 증가하고 D_stale(Δ=50) ≥ 2·D_noise, 이벤트
  정렬 점프가 보이면 P1 채택. D_stale ≈ D_noise 면 LLM은 국면을 못 읽는 것 —
  d_t 요약/프롬프트 문제이지 스케줄링 문제가 아니다(A축 ① 기각 또는 d_t 재설계).
- 비용: 32 ep × 11 시점 × 2 호출 ≈ 700 호출 ≈ 1 h.

### E2 — P2: 갱신 빈도 개입 (같은 체크포인트, 테스트 시 갱신 허용)
정책 고정, 테스트 시 갱신 스케줄만 바꾼다. 팔당 128 에피소드(승률 ±4%p).

| 팔 | 테스트 시 가이던스 | 호출/ep |
|---|---|---|
| A0 | 마스크 off | 0 |
| A1 | F=ep (시작 시 1회) — LEHCA 테스트 관행에 가장 가까운 공정 기준 | 1 |
| A2 | F_test=25 | ≈2 |
| A3 | F_test=10 | ≈5 |
| A4 | F_test=5 (사실상 오라클 신선도) | ≈11 |
| A5 (선택) | 이벤트 마커 시점에만 갱신 (수제 트리거) | 이벤트 수(≈2–3) |

- 지표: 승률, 리턴, 호출/ep, 그리고 기전 지표 — **역효과율** = 보유 g의 hard가
  g\*의 틸트 argmax를 금지한 스텝 비율, argmax 불일치율, 불일치 시
  ΔQ = Q(a_fresh) − Q(a_stale)(체크포인트 Q, 오프라인 비용 프록시). 이벤트 발생
  에피소드 부분집합과 미발생 부분집합으로 나눠 본다.
- **판정**: A4 − A1 ≥ +5%p(95% CI가 0 제외)이고 이득이 이벤트 발생 에피소드에
  집중되면 P2 채택. A5가 A2와 호출 수가 비슷한데 A3–A4에 근접하면 "빈도가 아니라
  타이밍"이라는 핵심 주장의 첫 증거. A4 ≈ A1이면 신선도가 배포 성능에 무관 →
  이 맵·β에서 ①은 성립하지 않는다.
- β 교란 확인: A1·A4를 β_test=0.3으로 반복(학습 β와 달라 분포 이동 주의). 여기서만
  차이가 나면 효과는 마스크 강도에 종속 — 결과 해석에 명시.
- 비용: 128 × (1+2+5+11) ≈ 2.4k 호출 ≈ 3.5 h (팔별 프로세스 병렬 시 vLLM 배칭으로 단축).

### 구현 (베이스라인 무변경, `algorithm/agsched/`)
- `LehcaRunner` 서브클래스를 runner `"sched"`로 등록: `f_update_test`(정수 또는
  `"ep"`), `shadow_every`, `shadow_repeats`, `beta_test`; shadow용 두 번째
  `LLMCommander` 인스턴스(캐시 off); 이벤트 마커·거리·ΔQ를 스텝별 JSONL로 기록.
- 틸트 argmax·ΔQ는 `mac.forward` 출력에 (hard, soft)를 각각 적용해 계산.
- 실행은 기존 `checkpoint_path=… evaluate=True test_nepisode=128` 경로 사용;
  스크립트 `scripts/run_sched_eval.sh`.

## 6. 범위 결정 (사용자 확인 필요)

1. **채널**: 마스킹 on(논문 충실, M5 어휘) + shaping을 기본 설정으로 하되, S4를 위해
   shaping-only도 스윕. — M5 판정에 조건부.
2. **비용 단위**: 1차 = LLM 호출 수(캐시 미스), 2차 = 벽시계. refresh 횟수 자체는 비용
   아님(키 적중 시 공짜).
3. **시간 범위**: training-time만. test 에피소드는 논문 프로토콜(최신 g, refresh 없음) 유지.
4. **λ·β 스케줄 고정**(B축은 범위 밖). 단 λ 감쇠가 v4에서 ~200k에 0이 되므로 shaping
   채널의 F 효과는 첫 200k에 국한됨을 명시.
5. **맵**: 2s3z(진행 중) → 5m6m(본 무대) → 3s5z(유해 레짐, 참고).
6. **판정 지표**: AUC_early + final(last-10%) + N. 시드 ≥3.

## 7. 리스크

- F 스윕이 2s3z에서 평평 → S7로 5m6m 확인 전엔 결론 금지.
- LLM-MARL(2506.04251)이 SC2에서 호출 게이트를 이미 보고 → 우리 차별점은 "규칙 수준
  가이던스의 staleness·churn·off-policy 버퍼"라는 **기전 분석**과 주기 스윕. 기전 없이
  게이트만 제안하면 증분 연구로 읽힘.
- 효과 낡음이 작게 나오면(S0 기각) "F_update 스케줄링"은 비용 문제로만 남는다 —
  이 경우 연구 프레임을 재검토.
